**离线钢琴采样接入 · 1.5.4**

资源位于 `web/samples/salamander/`，`manifest.json` 固定上游提交与每个文件的 SHA-256。`tools/vendor-salamander.cjs` 可从固定公开上游重新取得 MP3、原始 README 与来源声明。

`web/build.py` 校验全部 MP3 后，将 Base64 采样映射注入 `web/piano-audio.js` 并编译进单文件 HTML，同时将署名和上游 README 放入 APK assets。无运行时音源网络请求，HTML 可直接从本地文件打开；当前输出约 5 MB，低于原生启动的 8 MB 读取上限。

共享模块的 Interface：

- `context()`：取得唯一的 Web Audio 上下文。
- `prepare(pitches)`：在用户操作中启动声音、预先解码待播音符。计时播放应等待其完成，再确定起点。
- `note(midi, {at, duration, volume, release, onended})`：创建可取消的 Voice；省略 `at` 表示现在，`duration:null` 表示等待松键。返回的 `ready` 表示已安排发声或已取消，`release()` 提前松键，`stop()` 取消当前或未来声音。
- `silence()`：取消全部已播放、已排定和等待解码的 Voice。
- `status()`：只读诊断与测试数据。

Implementation 负责邻近采样变调、复用解码、48 MiB LRU 缓存、力度增益、衰减与压缩限幅。缓存上限不包含活动 Voice 引用的缓冲和解码临时内存。最多保存 128 个未结束 Voice，包含课程预先排定的音符。

调用方只管理自己的 Voice。课程暂停不挂起共享上下文；否则可能影响另一个工作区。后台切换由公共暂停与可见性处理共同清空声音；恢复时需新的播放操作。

识谱、专项与提示通过 `PianoHost.play()` 统一调用；课程示范在准备音色后确定节拍起点；曲谱欣赏、伴奏与回放在既有音乐时间上安排 Voice。节拍器和节奏点击保持独立短音，避免改变现有节奏任务的声音语义。

`tests/piano-audio.test.cjs` 用真实 Chrome/本地 MP3 验证发声、音域、半音比率、和弦、取消、共用上下文、缓存限额、调用方与离线性。原曲谱回归现在显式等待实际进入练习，再发送模拟 MIDI，覆盖首次解码造成的异步准备。
