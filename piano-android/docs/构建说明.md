# 开发与构建

源码位于 `piano-android/`；`web/` 为离线界面、训练规则和音频模块，`native/` 为 Android 宿主与 USB MIDI 通道。

需要 Python 3、Node.js、Java 17 及以上，以及 Android 构建工具。首次准备工具需要网络；运行中的应用不依赖网络。

从仓库根目录执行：

```sh
python piano-android/prepare_tools.py
python piano-android/web/build.py
python piano-android/build_apk.py
```

未在 PATH 中配置 Java 时，可通过 `PIANO_JAVA` 指定 Java 可执行文件。JavaScript 构建使用仓库内附的 Babel，不需要安装运行时 npm 依赖。

`build_apk.py` 使用已有的 `piano-android/signing/release.pk8` 和 `release.pem` 签名；密钥不随源码发布。缺任一文件就停止，不自动创建替代证书。自行构建须事先准备自己的签名，无法用不同签名覆盖安装官方 APK。升级交付必须核对旧APK证书指纹相同。输出名称来自manifest版本，不再硬编码。

输出文件位于根目录的 `deliverables/`。SDK工具、签名、构建输出和临时文件均被Git忽略。1.6.0本轮交付本地APK与GitHub源码；公开Release／二进制上传须另行授权。

核心检查可使用 Node.js 内置测试运行器，例如：

```sh
node --test piano-android/tests/*core.test.cjs piano-android/tests/song-learning.test.cjs
```

浏览器检查需要 Playwright 和 Chrome。部分脚本使用 Windows 的 Chrome 默认路径，其他系统需要按实际环境调整。开发过程与历史功能记录另存于 `开发与历史记录.md`。

## 平板布局回归

构建 HTML 后，以仓库根目录启动本地静态服务。浏览器打开 `piano-android/tests/layout-window.html?w=600&h=800`，该页用真实生产 HTML 填充指定的内容窗口。进入专项、做题、曲库或设置后，点击测试宿主底部“检查当前布局”，查看重叠、完成按钮命中、通用按钮尺度与对齐检查。该测试页不会打包进 APK。

至少覆盖 600、650、651、800、839、840、960、1280 宽以及 480 / 600 的短高窗口；切换曲库、设置、专注、键盘收起、暂停与输入设备。浏览器复现不代替安卓平板上的密度、安全区、IME 与 USB MIDI 验证。
